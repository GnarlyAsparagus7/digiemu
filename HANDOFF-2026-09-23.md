# Handoff — Digitakt mk1 emulator, 2026-09-23

Continues `HANDOFF-2026-09-22.md`. Same two trees, kept in step: WSL
`/root/digitakt/digikit` (the git repo) and `digikit-win`, which the GUI runs
from. **Nothing is committed** ("commit only when Em asks").

## The headline: live audio in real time, and patterns play

On 09-22 audio worked as render-then-play at 4.2% of real time (about 24 s of
wall time per second of sound). Now:

- **The GUI plays audio live at 48 kHz, in real time.** 100% of real time,
  no dropouts, 60-90 ms buffered, measured through the GUI's own emulator
  thread with a stub sound card. The recording correlates -0.994 with the
  loaded sample. Capacity is 1.4x real time on WSL with the sequencer
  running.
- **Patterns play.** STOP, grid-record trigs on steps 1/5/9/13, PLAY: the
  running light moves, TEMPO blinks, and the recording has every hit on a
  0.612 s grid (quarter notes at the project's 98 BPM) at equal level.
  `tools/livecheck.py --snapshot snapshots/Digitakt_OS1.53/loaded-sample.snap
  --pattern` re-checks all of this headless in about 30 s (exit 0 = every
  beat hit).

Details and numbers are in `DIGITAKT-MK1.md` under Audio ("Audio plays
live", "Patterns play"). What it took, in order of what it bought:

1. **`patches/unicorn-2.1.4-m68k-fast-mem.patch`.** Stock Unicorn sends every
   load and store through a C helper once any memory hook exists (our demand
   mapper is one), and its stubbed dirty bitmap sent every store through the
   self-modifying-code check. Hooks are now routed per page. 75% -> 175% of
   real time on the render benchmark.
2. **`patches/unicorn-2.1.4-m68k-digikit-accel.patch`.** ISA_C for the CFV4E
   (FF1 is an instruction, not a hook); a native block budget for the fast
   stepper; the render's software eDMA done natively. `emu/native.py` probes
   for it; without both speed patches the same run is ~9x slower and the GUI
   falls back to render-then-play at 2 kHz.
3. **Batched SSI, fast idle, and a 64M instructions/s emulated clock** after
   the intro (`[audio]` in `devices/digitakt.toml`).
4. **Refused timer ticks now wait** (`emu/pit.py`, `emu/dtim.py`). They used
   to be dropped; under the render's raised IPL most of DTIM3's 30 Hz ticks
   were lost and the UI ran 4 passes a second. Now 30-50.
5. **Software-forced interrupts on INTC0** (`emu/intfrc.py`, new). This is
   what the sequencer was missing. The render counts samples down and forces
   INTC0 source 44 (vector 108, level 5 — a source the RM lists as "Not
   used"); that handler forces source 57 (vector 121, level 2), which reloads
   the countdown. Neither was delivered, so the sequencer never ticked. 157
   ticks a second now: 96 PPQN at 98 BPM.

## Later the same day: headroom (the speed patch)

On a slow laptop (i5-1245U, Windows) live audio ran at 1.05-1.12x real time.
`patches/unicorn-2.1.4-m68k-digikit-speed.patch` (the sixth patch; both
installers pin it) takes the Windows capacity bench from 1.88-1.92x to
2.53-2.59x and the WSL deterministic replay from 1.72-1.97x to 2.69-2.83x,
with byte-identical audio and CPU state. What it does, from a profile taken
inside the library:

- **One helper per MAC** (`mac_fused`) instead of three, each of which synced
  the TCG globals: the EMAC was about a quarter of the run.
- **`NO_MEM_EXIT`**: no exit-request helper call after every guest load and
  store (12%). Those exist so a memory hook that calls `emu_stop` stops at the
  access; none of ours does, so `Machine` turns it on. Stock Unicorn also
  relied on that check to stop at a faulting store; the patch leaves the
  block from the store helper instead, so faults still stop at the faulting
  instruction (`tests/test_unicorn_speed.py` pins both).
- **`NATIVE_RTE`**: QEMU's ColdFire `rte` instead of the Python
  `UC_HOOK_INTR` pop, which stays as the fallback.
- **`NO_HOOK_PC_SYNC`**: memory hooks no longer re-translate the block to
  report the exact PC. GUI only (`emu/gui.py`), and off under
  `DIGIKIT_PIT3_PROBE=1`.

Everything degrades: on a five-patch library `emu/native.py` reports no
options and the Python paths run. `tools/capbench.py` (new) is the capacity
bench: it programs the pattern at real-time pace (pressed unpaced, DOWN
auto-repeats and YES lands in the file browser) and then measures with
pacing off; `--tracks N` programs N tracks and `--screens DIR` saves every
step. It and `tools/livecheck.py` now reuse one card copy in the temp
directory, since a mapped copy cannot be deleted on Windows and every run
leaked 1 GB. Numbers and the remaining profile are in `DIGITAKT-MK1.md`
("More headroom").

**More tracks cost almost nothing.** Eight tracks playing run at 2.46-2.56x
against 2.68x for one on Windows (0-6% in the WSL replay). The firmware
renders every voice every pass whether it plays or not: a guest profile of
the one-track and eight-track replays shows the same functions and the same
169-170M instructions per emulated second. The panel window costs about 3%.
So neither a thread per voice (it would need the voice render run natively)
nor the emulator in its own process has much to win; the levers are per
instruction. Details in `DIGITAKT-MK1.md` ("More tracks cost almost
nothing").


## Corrections to earlier write-ups

- **"The sequencer stalls after nine counts" was wrong about what it
  measured.** `0x4199e70c` is the render's write index (mod 32) into a
  32-record message ring at `0x4199e48c`, advanced when voice state changes;
  it is not a transport counter. The sequencer was not stalling, it was never
  being ticked. `0x4199dc30`/`0x4199dc31` (bytes) are the step and tick.
  `DIGITAKT-MK1.md` Known limits carries the correction; the old text stays
  as the record, and `docs/mk1/11-audio.md` now opens its sequencer section
  with the same correction. (Only documents 01–09 in `docs/mk1` are
  generated; 10 onwards are written by hand, so they can be edited directly.)
- **The software-eDMA segfaults have a measured cause**, and it is probably
  also the 09-21 8-of-8 (blamed then on garbage DMA parameters; not re-run).
  AddressSanitizer: `uc_mem_map` called from inside a memory write hook (the
  software eDMA mapping a page it was about to touch) resizes the TLB under
  the store in progress. Nothing maps from a hook now (rules in the
  `emu/edma_sw.py` docstring).
- `emu/edma_sw.py` ignored SMOD/DMOD; it wraps modulo now (channels 30 and 42
  use it).
- `tools/seqtest.py`'s `TICK_ISR = 0x4006e75a` is 4 bytes into the mk1
  vector-108 handler (`0x4006e756`), not an entry point, and nothing reached
  it because vector 108 was never delivered.
- The `pit.py` class docstring said holding refused ticks "halted the run at
  58.7M"; that attempt predates the non-destructive SR read and retried only
  at timer deadlines. The current version retries every 2048 instructions and
  passes everything.

## No Elektron bytes in the tree

Checked by searching every string (8+ characters) and every embedded byte blob
in the tree against the mk1 image, not by reading:

- **Signatures are digests now.** `emu/symbols.py` held 2,010 bytes of
  firmware code as search keys. Each is now an `H(n, wild, anchor, digest)`:
  length, wildcards, one instruction-sized anchor and 128 bits of SHA-256.
  Resolution on mk1 is identical, all 139 symbols and alternatives.
  `tools/mksig.py` prints the `H` to paste; `tests/test_symbols_hashed.py`
  fails if a literal signature is pasted back in.
- **The GUI draws the project's name**, not the product's wordmark, logo mark
  or tagline.
- **The console's service commands are not listed** beyond the `#HELLO`
  handshake the emulator's console tools use.
- What is left is small and functional: 79 bytes of container and section
  headers in `docs/mk1/01-container.md`, the 72-byte reset-handler fixture in
  `tests/test_early_init_contract.py`, and short quoted UI messages and class
  names.


## CI and merge protection

`.github/workflows/ci.yml` runs two checks on every pull request and every
push to `main`:

- `tests` builds the patched Unicorn (cached per patch set, since the emulator
  refuses stock Unicorn) and runs every test module with no firmware present,
  as a fresh clone would; `tools/ci/run-tests.sh` is the runner.
- `content-guard` (`tools/ci/content-guard.sh`) fails if a `.syx`, snapshot,
  card image, extracted section or other binary media is tracked, or any file
  is over 1 MB -- the things `.gitignore` keeps out and `git add -f` does not.

`tools/ci/protect-main.sh OWNER/REPO` makes `main` require both checks on an
up-to-date branch, a pull request, linear history, and no force-push or
deletion, for admins too. GitHub only allows branch protection on a public
repository or a paid plan.
