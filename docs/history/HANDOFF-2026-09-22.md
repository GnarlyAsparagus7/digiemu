## The headline: a sample loads into a project

On 09-21 the top roadblock was "no +Drive writer; it unblocks sound". The
writer then existed, but nothing it wrote was usable by the firmware, for
three independent reasons — each found by measurement, each fixed:

1. **The +Drive was never mounted.** The firmware accepts only seven known
   eMMC parts; the emulated card reported a known manufacturer with an empty
   product name, so identification returned -2 and the mount was skipped.
   Opening SETTINGS > SAMPLES then fed a NULL name to `std::string`, which
   threw into an empty `while(true)` abort handler — the "frozen screen".
   Fixed in `emu/esdhc.py`.
2. **Every directory looked empty.** The firmware lists directories only
   through three sorted indexes in each directory's second extent;
   `tools/ekfsadd.py` wrote them as zeros.
3. **"SAMPLE MEMORY FULL" on load.** Memory was fine — that text is just what
   the load-done callback shows for a count of zero. The files were WAVs with
   no content hash; the firmware wants its own sample format and resolves
   samples by a hash in inode `+0x0c`.

Result, from replaying the user's own button session against the final
ladder: browse to `/incoming`, tick the bell sample, FUNC menu,
LOAD TO PROJ, confirm → **"1 SAMPLE LOADED"**. **Hearing it is the next step.**

Every fix needed the ladder cold-rebuilt, because the card is identified in
the first 60M instructions and mounted before the 280M rung, and a resume
re-runs neither. The single most important thing to know about this
emulator: **anything the firmware reads from the card at boot is frozen into
every snapshot.**

## What changed, in order

**Mount** — `emu/esdhc.py`: CID carries a whitelisted part (`0x11` /
`004GE0`) plus the three EXT_CSD identity bytes and the SLC sector count
(`0x3b0000`) the same check compares. `Esdhc` boots against the configured
`DT2_PLUSDRIVE` image instead of a blank in-memory card.

**Directory indexes** — `tools/ekfsadd.py` builds hash / name / inode indexes
by replaying the firmware's insert `FUN_400cd04c`. Hash is ext3's legacy
`dx_hack_hash`; name order is a natural, case-insensitive compare with a
quirk (the byte after an equal digit run is never read). A fresh format is
byte-identical to a firmware format on every directory block. `--repair`
rebuilds indexes on an old card. Inode `+0x02` is a link count, not an entry
count.

**Sample files** — a sample is a 64-byte header (`+0x04` PCM bytes, `+0x08`
rate, `+0x14` `0x7f`), big-endian 16-bit mono PCM, 16 zero bytes. Every
finished file is hashed: lookup3 over the whole file, seed `0x654c654b`
("eLeK"), `| 1`, into inode `+0x0c` and an on-card table at data block 64;
the mount indexes it and projects find samples by it. `ekfsadd.py` now
converts WAVs (8/16/24/32-bit, float, any channels → mono), hashes every
file, records the parent in `+0x08`, and its format clears the reserved
blocks. The hash and compare were each verified by running the firmware's
own routines under Unicorn. Full format in `docs/mk1/10-plusdrive.md`.

**From upstream digikit** (fork is 68 ahead / 82 behind; most upstream work is
Digitakt II SHARC and does not apply): `emu/semscan.py` (never-fake semaphore
list for `unblock`; needed `give`/`give_b` resolved per image — mk1 is
+0x2e4; measured effect on mk1: none), `tools/symaudit.py` +
`tests/test_symaudit.py`, `tools/emucheck.py` (mk1-adapted "is this run
trustworthy"; verified to fail on an incomplete boot as well as pass), and a
`SigAt` rule nothing on mk1 needs yet.

**INTC** — the firmware masks and unmasks only by writing a source index to
`SIMR`/`CIMR`, never `IMRH`/`IMRL`. We model neither, so masks are dropped
and anything with a nonzero ICR is always deliverable. Verified, not yet
modelled. `emu/pit.py`'s comment calling `0xfc050014` IMRL was wrong — INTFRCL.

## Method that paid off: replay the user's session

The GUI logs every panel message it feeds as `[gui] input --feed INSTR:HEX`.
Resuming the same snapshot against a byte-identical card and feeding the same
bytes at the same instruction counts reproduces a session exactly — the load
pre-check fired at 403.1M in both the live GUI and the replay. That turned
"it says SAMPLE MEMORY FULL" into a trace of every step of the loader in one
run, with no guessing at key combos. The scratchpad tools are `replay.py`
(replay with probes) and `decodelog.py` (turn the log back into key codes,
chords included). Worth promoting into `tools/`.

## Key names: settled, and NO fixed (corrects an earlier version of this section)

The `devices/digitakt.toml` labels were right except NO. The doubts came from
headless screenshots, not the firmware: `panel_diff` (`FUN_400e60e2`) sends
the frame at `[0x4020d8f8]` and then swaps the pointers, so reading
`[0x4020d8f8]` after a spin returns the frame from one key earlier. The GUI
latches at the diff entry and was never affected. In scripts, latch at
`prof.panel_diff` or read `[0x4020d8fc]`.

**NO is code 13.** A sweep of all 48 codes, latched properly, found 13 is the
key that backs out (SETTINGS -> main page, browser -> SETTINGS). The GUI's NO
button had been sending code 0, which is not a key at all (the firmware's
panel-test names list 23 function keys, codes 1-23), and 13 was drawn as a
separate PATTERN MENU button. Fixed in `devices/digitakt.toml` and
`emu/dtpanel.py`; details in `DIGITAKT-MK1.md`.

## Key LEDs: working

The UART8 stream to the panel MCU is decoded (`emu/panelleds.py`, format in
`DIGITAKT-MK1.md`), seeded from the firmware's RAM shadow on resume, and drawn
by `dtpanel` as lit keys plus four pattern-page LEDs under PAGE. The LED ->
key map is `[panel.leds]` in `devices/digitakt.toml`. Tests:
`tests/test_panelleds.py`. The seed addresses are OS 1.53 literals, used only
for that version and only if the RAM looks like the shadow.

## Audio: working, as render-then-play (09-23)

The silence was the patched Unicorn's EMAC: fractional mode (MACSR `0xA0`,
the engine) multiplied unsigned without the `<< 1`, and integer mode had S/U
backwards so the `0x80` mix saturated negatives to 0. Third patch
`patches/unicorn-2.1.4-m68k-emac-modes.patch`; both venvs rebuilt (backups of
the old libraries sit beside them as `*.pre-fractional`). The captured output
now matches the loaded sample (correlation -0.992). The installers take a
local clone (`UNICORN_GIT=` / `-Source`) so a rebuild needs no download; the
clone used lives in the session scratchpad, so the next rebuild will fetch
from GitHub unless pointed elsewhere.

The GUI records at a 2 kHz emulated audio clock and plays back at 48 kHz:
PLAY / CLEAR / SAVE WAV in the panel header, ~24 s of wall time per second of
sound. Real time needs ~36x more speed; see `DIGITAKT-MK1.md`. To hear a
loaded sample: SRC page, encoder D to open the slot list, pick it, YES, then
the trig, wait, PLAY. `tests/test_unicorn_compat.py`'s installer dry-run test
cannot run on Windows (it calls `bash`); everything else passes on both.

## Corrections made to earlier write-ups

- `0x426856b0` is the **open-files** bitmap (set on open, cleared on close),
  not the block bitmap; its zeros were evidence of nothing.
- The "format matches the device byte for byte" claim from 09-21 did not
  cover directory blocks, which is where the index bug was.
- The earlier "enumeration never runs" came from a coverage diff against an
  idle baseline, which hides anything that also ran in the baseline. The raw
  count was needed. Diff windows answer "what changed", not "what ran".

   reschedule requested by `bset #13` on `0xfc050014` never delivers.
5. Resampling: samples keep their source rate in the header, which the
   engine accepts, but only 48000 is confirmed from a firmware writer. If a
   44.1 kHz sample plays off-pitch, resample to 48 kHz in `wav_to_sample`.

   Benign-looking; not investigated.
