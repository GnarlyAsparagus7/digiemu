## How to read the confidence column

The rule type *is* the confidence. These are not the same kind of
knowledge and should not be trusted equally:

| rule | confidence | what it means |
|---|---|---|
| `AnyOf` | mixed | first sub-rule that resolved wins; see the detail column for which one |
| `Offset` | derived | a fixed offset from another symbol |
| `Operand` | derived | an integer read out of another symbol's instruction stream |
| `OperandGroup` | derived | distinct absolute operands scanned from another symbol's code |
| `Pick` | derived | one element of a resolved group |
| `ScanAll` | measured | every match of a pattern in the image |
| `Sig` | measured | unique masked byte-signature match in this image |

Counts by confidence: mixed 28, derived 28, measured 20, unclassified 4

## Unresolved — where the emulator is guessing

These are looked for and not found. Anything that depends on one
of them is unavailable, and code that silently degrades when a
symbol is `None` will do so here.

Every one is OPTIONAL. What each absence actually costs was
established by reading its consumers in `emu/` and `tools/`, not
assumed — an unresolved optional symbol is usually a switched-off
log line, not a broken emulator.

| symbol | impact | why it did not resolve |
|---|---|---|
| `px_copy` | **diagnostic only** | 0 match(es) for masked signature (32 bytes), need exactly 1 |

- **`px_copy`** — emu/longrun.py uses it for a counter, ev['pxcopy']; absent, that counter stays 0. This one appears GENUINELY ABSENT from mk1 rather than merely unfound: px_copy_to_bitmap(PixelData&, Bitmap&) is a Digitakt II routine, and mk1 carries no "PixelData" string, no match for its two-pointer prologue, and every function Ghidra reports as calling set_pixel is a drawing routine rather than a buffer copy. mk1 renders through panel_diff and the fb_front/fb_back pair instead.

The one unresolved symbol does not affect emulation correctness.
