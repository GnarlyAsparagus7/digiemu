# 05 — RTOS tasks

Generated by `tools/mk1doc_tasks.py`. Machine-readable:
`facts/tasks.json`.

`python -m emu.tasks` walks the **ready list**, which on this firmware
holds a single node — everything else is blocked on something and so
is not on it. That is why it prints almost nothing here. The full
inventory has to be captured as tasks are **created**, which means
running the boot rather than reading a snapshot.

Captured over 160M instructions from `boot400M.snap`.

## TCB layout

Derived from the context switcher at `0x40000410` — see
`emu/tasks.py`, which reads the layout out of the instruction stream
rather than assuming it.

| field | offset |
|---|---|
| next pointer | `+0x00` |
| d0–d7 then a0–a7 | `+0x0C` |
| saved a7 | `+0x48` |

## Scheduler priority walk

Every task the scheduler knows about, read from its own priority
array rather than from what this run happened to watch being
created. Each slot is a circular doubly-linked list, so the walk
stops when it returns to a node it has seen rather than on a null.
Entry points are only known for tasks caught being created.
