# 03 — Hardware the firmware actually touches

Generated by `tools/mk1doc_mmio.py`. Machine-readable: `facts/mmio.json`.

Method: every 32-bit big-endian value in the decompressed MAIN OS that
lands in an MMIO window, grouped into 16 KB blocks (the MCF5441x
peripheral stride) and named from
`docs/contracts/mcf5441x-reference-v1.json`.

**Caveat, which bounds every number below:** a constant that equals a
peripheral address is *evidence*, not proof — it could be data. The
corroborating signal is clustering: real use produces many distinct
offsets inside one block, a coincidence produces one value alone. The
`distinct offsets` column is therefore more meaningful than `refs`.

## Which peripherals the firmware powers up

`PPMCR0`/`PPMCR1` take a **module number** and enable that module's
clock. The set of values written to them is therefore an authoritative
list of the hardware this firmware turns on — stronger evidence than
counting address references, because a module with no clock cannot
respond at all.

Register addresses from Linux `arch/m68k/include/asm/m5441xsim.h`:
`MCFPM_PPMSR0` `0xfc04002c`, `MCFPM_PPMCR0` `0xfc04002d`,
`MCFPM_PPMSR1` `0xfc04002e`, `MCFPM_PPMCR1` `0xfc04002f`.

**PPMCR0 (enable)** — 11 module(s): `0x0F` (15), `0x11` (17), `0x12` (18), `0x13` (19), `0x14` (20), `0x17` (23), `0x1D` (29), `0x1F` (31), `0x20` (32), `0x24` (36), `0x2C` (44)

The slot number in the MCF5441x memory map **is** the PPMCR module
number, so each one has a name. Source: MCF5441x Reference Manual
Rev 5, Table 1-3, chapter 1 page 1-17.

| module | peripheral | corroborated by |
|---|---|---|
| `0x0F` (15) | DSPI 1 | 47 references to DSPI1 |
| `0x11` (17) | eDMA controller | 213 references to eDMA |
| `0x12` (18) | Interrupt controller 0 | INTC0 referenced; vectors 64-121 in use |
| `0x13` (19) | Interrupt controller 1 | INTC1 referenced; vectors 128-191 in use |
| `0x14` (20) | Interrupt controller 2 | INTC2 referenced; vectors 192-223 in use |
| `0x17` (23) | DSPI 0 | 313 references -- the most-referenced block in the image |
| `0x1D` (29) | DMA timer 1 | vector 97, one of only two DMA timers with a handler |
| `0x1F` (31) | DMA timer 3 | vector 99; dtim3_init writes 0x1F here before installing it |
| `0x20` (32) | PIT 0 | vector 205 (PIT0), which points at ctx_switch |
| `0x24` (36) | Edge port 0 | vectors 66 and 67, both acking 0xFC090003/6 |
| `0x2C` (44) | USB On-the-Go | 143 references and vector 209 |

Every enabled module is independently corroborated by the reference
counts above or by an installed vector in `04-vectors.md`. Nothing here
rests on the module table alone.

**Not enabled, but referenced:** SSI1 (`0xFC0C8000`, module 50) is
written by an init function at `0x40000F80`–`0x40001010` — 21
references across 7 register offsets — yet module 50 never appears in
MAIN OS's PPMCR writes. Whether its clock is enabled elsewhere (the
bootstrap, section id 2) is **not established here**. This matters:
SSI is the audio serial interface, and an earlier note in this project
recorded "zero references to SSI0/SSI1" — that was checked against
`0xFC0BC000`/`0xFC0C0000`, and `0xFC0C0000` is the PLL, not SSI1.
