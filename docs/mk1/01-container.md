## Layer cake

| # | layer | what it is |
|---|---|---|
| 1 | MIDI SysEx | `F0 00 20 3C <dev> 00 <cmd> ... F7` messages |
| 2 | 8-in-7 | MIDI is 7-bit; each 7 data bytes carry a leading high-bit byte, MSB first |
| 3 | preamble | 8 bytes; bytes 4..8 are a 32-bit content checksum |
| 4 | ELE3 | magic, then a section table of 16-byte entries |

Nothing is encrypted and nothing is signed.

### Which fields the firmware actually reads

MAIN OS loads the 32-byte header into a buffer at `0x421ED5A8` — found
by the magic comparison, `move.l #"ELE3",d0` then `cmp.l (abs).l,d0`,
at `0x400E8974`. Counting absolute references to each field in that
buffer says what is used:

| field | absolute references |
|---|---|
| `+0x00` magic | **3** |
| `+0x1C` section count | **1** |
| `+0x04`, `+0x08`, `+0x0C`, `+0x10`, `+0x14`, `+0x18` | **0** |

The build and version strings are read **register-relative** rather
than absolutely — `docs/FINDINGS.md` establishes that the container
arrives in a register, which is why no absolute reference exists — so
their zero counts are expected.

`+0x04` (= 44) and `+0x18` (= 0) have no consumer this analysis can
find. They are recorded with their measured values; nothing in the
emulator depends on them.

## Sections stored raw, not compressed

A section is packed only when its 8-byte header is
self-consistent: the declared length fits and the bytes after it
sum to the declared sum. Two sections here fail that test not
because they are corrupt but because they are **not compressed**.
